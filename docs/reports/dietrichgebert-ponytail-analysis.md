## What it is

Ponytail is an agent skill that makes an AI coding agent behave like "the laziest senior dev in the room": before writing any code, it must justify that the code needs to exist at all. The pitch is one persona — long ponytail, oval glasses, replaces your fifty lines with one — but the substance is a short ruleset (the main skill is 120 lines of Markdown; all six skills together are 460 lines) injected into the agent's context, plus adapters that load that ruleset into roughly twenty different agent harnesses: Claude Code, Codex, GitHub Copilot CLI, OpenCode, Gemini CLI, Cursor, Windsurf, Cline, Kiro, Zed, and more.

It went viral fast — from launch to ~101k stars in about two months — then survived a public benchmark debunking by correcting itself, which is the most interesting part of the story (covered below).

Ponytail governs what the agent *builds*, not how it *talks*. That makes it the code-side complement to the prose-side skills this repo already vendors: humanizer cleans up the writing, ponytail keeps generated scripts and tools small.

## The ladder

The core is a seven-rung decision ladder the agent must stop at, first rung that holds:

1. Does this need to exist at all? (YAGNI)
2. Already in this codebase? Reuse it.
3. Stdlib does it? Use it.
4. Native platform feature covers it? (`<input type="date">` over a picker library, CSS over JS, DB constraint over app code)
5. Already-installed dependency solves it? Use it.
6. Can it be one line? One line.
7. Only then: the minimum code that works.

Crucially, the ladder has explicit floors that are never cut: input validation at trust boundaries, error handling that prevents data loss, security, accessibility, and anything the user explicitly asked for. Two more rules give it teeth in practice: bug fixes must fix the root cause in the shared function rather than patch the symptom path, and non-trivial logic must leave one small runnable check behind (an assert-based self-check or one small test file — "lazy code without its check is unfinished"). Deliberate corner-cuts get marked with a `ponytail:` comment naming the ceiling and the upgrade path, and a companion skill (`/ponytail-debt`) harvests those comments into a ledger later.

Three intensity levels: `lite` (build what's asked, name the lazier alternative), `full` (ladder enforced — the default), `ultra` (YAGNI extremist, challenges the requirement itself). `off` and plain-English "stop ponytail" turn it off.

## Repository anatomy

~130 files, 2.2 MB. The design principle (documented in `docs/agent-portability.md`) is that `skills/` holds the behavior and everything else is a thin adapter:

| Area | Role |
|------|------|
| `skills/` | Source of truth: 6 skills — `ponytail` (the mode), `-review` (over-engineering-only diff review), `-audit` (whole-repo version), `-debt` (harvest `ponytail:` comments), `-gain` (benchmark scoreboard), `-help`. |
| `AGENTS.md` | The compact always-on ruleset for hosts that just read instruction files (Zed, Amp, Jules, Codex extension, CodeWhale…). Adapter rule copies in `.cursor/rules/`, `.windsurf/rules/`, `.clinerules/`, `.kiro/steering/`, `.qoder/rules/`, `.github/copilot-instructions.md` are kept aligned by CI. |
| `hooks/` | The Claude Code / Codex plugin tier: Node lifecycle hooks. `SessionStart` injects the mode-filtered ruleset every session; `UserPromptSubmit` tracks `/ponytail` mode switches in a flag file; `SubagentStart` re-injects into every spawned subagent (scopable via a `PONYTAIL_SUBAGENT_MATCHER` regex). Plus optional statusline badge scripts (`[PONYTAIL:ULTRA]`). |
| `commands/*.toml` | The six slash commands. |
| `.opencode/`, `pi-extension/`, `gemini-extension.json`, `__init__.py` + `plugin.yaml` (Hermes, in Python), `.qoder-plugin/`, `.grok-plugin/`, `.devin-plugin/`, `.openclaw/` | Per-host plugin adapters, each reusing `skills/` and the shared instruction builder. The OpenClaw copies are generated by script; CI fails if they drift. |
| `ponytail-mcp/` | A small MCP server (stdio) serving the ruleset as a prompt and a tool, for hosts whose only injection point is the prompt menu. |
| `benchmarks/` | The full benchmark harness and dated result writeups, including the self-correction. |
| `examples/` | 11 before/after transcripts from real benchmark runs (e.g. debounce: 116 lines without, a few with). |
| `tests/`, `scripts/`, `.github/workflows/` | 84-test suite, rule-copy and version-sync checkers, CI that runs all of it on every push and PR. |

Config surface: `PONYTAIL_DEFAULT_MODE` env var or `~/.config/ponytail/config.json`; mode state is a flag file under `~/.claude` (or the host's plugin-data dir). `scripts/uninstall.js` cleans all of that up and only removes a statusline entry it installed itself.

## The benchmark story

This is the repo's defining episode and the reason to take it more seriously than the average viral prompt repo.

The launch benchmark claimed **80–94% less code**. On June 16, Colin Eberhardt (Scott Logic) opened [issue #126](https://github.com/DietrichGebert/ponytail/issues/126) and published a blog post showing the claim was inflated: the baseline was a bare, chatty model that padded answers with prose and multiple options, single-shot generation isn't how agents are used, safety wasn't measured, and a seven-word prompt ("Follow YAGNI principles, and prefer one-liner solutions") could beat ponytail on its own benchmark.

The maintainer's response, written up in `benchmarks/results/2026-06-18-agentic.md`, restates the critique fairly and rebuilds the benchmark to be able to *disprove* the skill: real headless Claude Code sessions editing a real pinned repo (fastapi/full-stack-fastapi-template), LOC counted from the `git diff` left behind, n=4 per cell, four arms including Eberhardt's own prompt, and an adversarial safety tier that executes the produced code against path traversal, SQL injection, forged tokens, and malformed input. The writeup even discloses a contamination bug they caught before publishing — the plugin's SessionStart hook was firing on the baseline arm too, so the baseline was secretly running ponytail.

The corrected headline (Haiku 4.5, 12 feature tasks): **−54% LOC on average** (range ~0% on already-minimal CRUD code to −94% where there's an over-build trap — date picker 404→23 lines because it reaches for `<input type="date">`), −22% tokens, −20% cost, −27% time, and 100% safe. The seven-word prompt cut less (−33%), was erratic (above baseline on some tasks), and was the only arm that dropped a security guard — it wrote the fewest lines on a path-join task by omitting the traversal check once in four runs. Ponytail's kept ~3 extra lines *were* the check. The README now leads with the corrected numbers and links the critique; InfoQ covered the episode as a maintainer correcting his own benchmark after a challenge.

Caveats that remain: one model (Haiku 4.5) at n=4, the safety tier is a floor (six deterministic checks, not a security proof), and the README itself notes the token/cost savings can invert on terse reasoning models that spend thinking tokens deliberating the ladder (it names GPT-5.5). Press skepticism about prompt-benchmark methodology generally (LLM-judged, self-scored) still applies to the category, and the pseudonymous single-maintainer identity remains an open question in coverage.

## Quality assessment

For a repo whose product is ~460 lines of Markdown, the engineering around it is unusually careful:

- I ran the full suite in the clone: 83/84 pass. The one failure is the CSV correctness check, which needs `pandas` locally — a documented dependency this container lacks (CI installs it explicitly; the test is real, not rot).
- `scripts/check-rule-copies.js` passes (9 rule invariants verified present in `SKILL.md`, `AGENTS.md`, and every adapter copy) and `scripts/check-versions.js` passes (8 version files pinned at 4.9.0). Drift between the many host adapters — the obvious failure mode of this architecture — is CI-enforced, not convention.
- I read every file on the hook execution path (`hooks/*.js`, the OpenCode/pi/Hermes/MCP adapters): **no network I/O, no shell execution, no telemetry**. The hooks only read stdin/env and write a mode flag file. The statusline nudge asks the agent to *offer* a settings change once, flags that it asked, and refuses to embed install paths containing shell metacharacters (an allowlist in `isShellSafe`). Failure philosophy is never-block: silent fails, a 1-second stdin fallback timer for a Windows freeze bug, 5s hook timeouts.
- It dogfoods. `AGENTS.md` ends with "Yes, this file also applies to agents working on the ponytail repo itself," and the source carries its own `ponytail:` ceiling comments with issue references (#443, #528, #377…).

Caveats worth knowing:

- The Claude Code plugin tier runs Node on every prompt; `node` must be on the non-interactive PATH or activation stays silently off (skills still work).
- It's opinionated by design. `full` mode will answer a request for a component library integration with a native HTML element and two lines of justification. That's the point, but developers who wanted the scaffold will notice. `ultra` argues back; keep it for cleanup days.
- Single pseudonymous maintainer, plus early commercial signals (a "something's coming" waitlist at ponytail.dev, a sponsor logo). MIT license and a vendorable 120-line skill file make lock-in risk near zero, but the plugin-marketplace install channel depends on the upstream repo.

## Fit for ClawTeam / AIOC

Most of what this repo ships is documents, but `tools/` is meant to grow scripts and utilities for construction workflows (takeoff parsers, register generators, schedule munging), and those get written almost entirely by Claude sessions. That's exactly the code ponytail is for:

- Agent-written utilities drift toward over-engineering precisely because nobody on a GC team reads them closely. A discipline that produces a 30-line script instead of a 300-line mini-framework is worth real maintenance money here.
- The safety floors matter for us: tools that parse externally-supplied files (vendor CSVs, drawing exports, submittal PDFs) keep their trust-boundary validation under ponytail; the benchmark showed it's the bare "write less" prompt that drops those guards.
- The `ponytail:` comment + `/ponytail-debt` ledger convention fits how this team defers work: a deliberate corner cut in a tool gets a named ceiling instead of a silent one.
- `/ponytail-review` is a useful pre-merge pass on tool PRs — it only hunts complexity and explicitly routes correctness/security to a normal review.
- No conflict with the document work: ponytail scopes itself to code and stays out of prose ("governs what you build, not how you talk"), so it composes cleanly with the vendored humanizer skill (prose) rather than competing with it.
